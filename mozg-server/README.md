# Мозг Иваныча — доработка рабочего сервера

Здесь лежат изменённые файлы работающего пилота `mozg_ivanycha_pilot_v0_2`
(сервер `mozg.ivanychprofi.ru`, Python + SQLite + Docker + Caddy).

**Оригинальный проект целиком здесь не хранится** — только те два файла,
которые меняются. Остальное на сервере остаётся как есть.

## Что добавлено: модуль 1 «Клиенты и объекты»

### Новый раздел меню «Клиенты»
* Карточка клиента: частное лицо или организация, контакты, адрес, источник обращения,
  ответственный сотрудник, комментарий.
* Реквизиты для документов: паспорт (для физлиц) либо ИНН / КПП / ОГРН / банк / БИК /
  расчётный счёт / подписант (для организаций).
* Объекты клиента: название, адрес, площадь, высота потолков, статус,
  замерщик / дизайнер / прораб, номер договора в старой системе.
* **Помещения объекта с габаритами** — длина, ширина, высота, двери, окна.
  Площадь пола, стен (за вычетом проёмов) и периметр считаются автоматически,
  прямо во время ввода. Это основа для следующего модуля — калькулятора смет.
* Архивирование клиентов и объектов (данные не удаляются).

### Конструктор прав (раздел «Пользователи»)
Двухслойная система доступа:
1. **Роль → разделы меню.** Право `page.<раздел>` включает или выключает
   раздел для всей роли. Настраивается переключателями, без правки кода.
2. **Точечные права внутри модуля**, например:
   * `clients.view` — видеть список клиентов;
   * `clients.edit` — создавать и править;
   * `clients.requisites` — видеть паспорт / ИНН / счёт (для замерщика по умолчанию
     выключено — он видит клиента, но не его паспортные данные);
   * `objects.view` / `objects.edit` — объекты клиента;
   * `admin.users`, `admin.perms` — администрирование.
3. **Личные исключения на сотрудника** поверх роли: «по роли / разрешить / запретить».

Собственник (`owner`) всегда имеет полный доступ независимо от переключателей —
защита от случайной потери доступа.

### Исправления в существующем коде
* `bind()` обращался к элементам по «голым» именам (`saveplan`, `newpay`…), из-за чего
  на страницах без этих элементов выполнение прерывалось с ошибкой. Переписано
  через `getElementById`.
* Добавлено правило `[hidden]{display:none!important}` — без него атрибут `hidden`
  не срабатывал на элементах с `display:grid`.
* Функция `openObject` для legacy-объектов переименована в `openLegacyObject`,
  чтобы не конфликтовать с новой функцией объектов клиента.

## Новые таблицы в базе

Создаются автоматически при запуске, существующие данные не затрагиваются:

| Таблица | Назначение |
|---|---|
| `clients` | карточки клиентов |
| `client_objects` | объекты клиента, помещения хранятся в поле `rooms` (JSON) |
| `role_perms` | права роли (включая `page.*`) |
| `user_perms` | личные исключения сотрудника |

При первом запуске `role_perms` заполняется из текущего `ROLE_PAGES` и значений
по умолчанию, поэтому доступы остаются такими же, как были, — и дальше их можно
менять через интерфейс.

## Новые API-эндпоинты

`GET /api/clients`, `GET /api/client?id=`, `GET /api/staff`, `GET /api/perms`,
`POST /api/client-save`, `POST /api/client-archive`, `POST /api/object-save`,
`POST /api/object-archive`, `POST /api/role-perms`, `POST /api/user-perms`.

## Как поставить на сервер

```bash
cd /root/mozg_ivanycha_pilot_v0_2

# 1. Резервная копия
cp server.py server.py.backup-$(date +%F)
cp static/app.html static/app.html.backup-$(date +%F)
cp mozg_pilot.db mozg_pilot.db.backup-$(date +%F) 2>/dev/null

# 2. Новые файлы
BR=claude/estimate-calculator-role-cabinets-50uiw6
RAW=https://raw.githubusercontent.com/ivannychpro-cpu/ivanych-smety/$BR/mozg-server
curl -fsSL -o server.py      "$RAW/server.py"
curl -fsSL -o static/app.html "$RAW/static/app.html"

# 3. Перезапуск
docker compose restart
```

## Откат, если что-то не так

```bash
cd /root/mozg_ivanycha_pilot_v0_2
cp server.py.backup-$(date +%F) server.py
cp static/app.html.backup-$(date +%F) static/app.html
docker compose restart
```

Откат безопасен: новые таблицы в базе просто перестают использоваться,
старые данные не меняются.

## Проверено перед выкладкой

Локальный запуск с тестовой базой, проверка в браузере:
создание клиента и объекта, автоматический пересчёт площадей при вводе габаритов,
сокрытие паспортных данных от роли «Замерщик», включение и выключение раздела
«Клиенты» через конструктор прав с проверкой под логином замерщика,
работа существующих разделов (объекты, подотчёт, заявки на оплату, пользователи).
